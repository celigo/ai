# Diagnosing NetSuite Steps

How to configure NetSuite exports, imports and connections is in [configuring-exports](../SKILL.md), [configuring-imports](../../configuring-imports/SKILL.md) and [configuring-connections](../../configuring-connections/SKILL.md), with their schemas. This reference is for a NetSuite step that fails, stalls or returns nothing: the checks that reach into the NetSuite account, the errors NetSuite steps return, and the traps that fail without an error.

- **CLI:** `celigo connections ping`, `celigo connections suiteapp-status`, `celigo metadata types|fields`, plus the run and error commands in [troubleshooting-flows](../../troubleshooting-flows/SKILL.md).
- **MCP:** the deployed server has no tool for a connection ping, the SuiteApp check or metadata. Run them with the CLI, or through the REST API: `GET /v1/connections/{_id}/ping`, `GET /v1/connections/{_id}/distributed` and `GET /v1/connections/{_id}/distributedApps`.

## Check the NetSuite Side First

When every NetSuite step on a connection fails, or a listener or a NetSuite DA import never gets anywhere, check the account before the step:

```bash
celigo connections ping <connectionId>                  # credentials and reachability; answers 200 either way, so read the body
celigo connections ping <connectionId> --distributed    # the Celigo SuiteApp or bundle RESTlet in the account
celigo connections suiteapp-status <connectionId>       # which of the SuiteApp and the bundle are installed, and their versions
```

- **The distributed ping** is a live round trip to the Celigo SuiteApp or bundle RESTlet that NetSuite listeners and NetSuite DA imports run through. It takes a few seconds and returns `{success, statusCode, resBody, bundleURL}`. Run it before building either.
- **`suiteapp-status`** reports the SuiteApp and the legacy bundle separately (`{bundle, suiteapp}`). Trust it over the connection's `netsuite.suiteAppInstalled`, which only records what was detected the last time the connection authenticated.

## Errors on NetSuite Steps

| Error | Where | What it means | What to do |
|---|---|---|---|
| HTTP 400 `SSS_REQUEST_LIMIT_EXCEEDED` (RESTlets), HTTP 429 (REST web services), `ExceededConcurrentRequestLimitFault` or `WS_REQUEST_BLOCKED` (SOAP), "Only one request may be made against a session at a time" | Any step on the NetSuite account | The account's concurrency limit is spent. Every connection to the account and every caller outside Celigo share it, and NetSuite refuses all of them at once, so a step can fail with nothing changed on its own connection. On RESTlet and SOAP calls the platform retries `SSS_REQUEST_LIMIT_EXCEEDED`, `WS_REQUEST_BLOCKED` and `WS_CONCUR_SESSION_DISALLWD` once a second, for up to about five minutes by default, before the step fails, so a run can sit still that long first | Total the ceilings of every connection to that account and keep them, with the outside callers, within its limit, or have the connections borrow from one parent ([Connections as concurrency queues](../../configuring-connections/SKILL.md#connections-as-concurrency-queues----throughput-and-governance)) |
| 403 `FEATURE_DISABLED` "The 'REST Web Services' feature is not enabled" | Every SuiteTalk REST and SuiteQL call | NetSuite's REST Web Services feature is off | A NetSuite administrator enables it (Setup > Company > Enable Features > SuiteCloud); custom RESTlets don't need it ([gotcha 12](../SKILL.md#gotchas)) |
| `sss_invalid_srch_operator` | A saved-search or lookup criterion | A numeric operator (`equalto`, `greaterthan`, `between` and the like) on a text column: the platform turns a templated `searchValue` into a number for them | Compare text and checkbox columns with `is` / `isnot`, and list or select columns with `anyof` / `noneof` and an array `searchValue` |
| `[search_not_sorted]` | An ad-hoc RESTlet search (criteria and columns, no saved search) | Grouping needs the search sorted by internal id | Set `netsuite.skipGrouping: true` ([gotcha 6](../SKILL.md#gotchas)) |
| `STATIC_MAPPING_ERROR` "Exported value is empty/undefined for the field: $.<path>" | A NetSuite DA lookup set with `searchField` and `operator` | The record's value for the search is empty | Fill the value upstream, or set `allowFailures: true` with a `default` |
| `VALUE_LOOKUP_FAILED` | A NetSuite DA lookup set with an `expression` | No match, or more than one | [configuring-imports > Common Errors](../../configuring-imports/SKILL.md#common-errors); a single match can be wrong too (below) |
| `Failed to create, update/transform record because <message>` or `Failed to save record because <message>` | A NetSuite DA import | The Celigo SuiteApp or bundle puts NetSuite's refusal in one of these sentences and keeps NetSuite's code. *create, update/transform* means NetSuite refused while the record was being created, loaded or transformed and its fields set, before any save; *save* means NetSuite refused the save itself. `because null` means NetSuite's error carried no message | Read the code and the text after `because` as NetSuite's error. With `null`, read the calls the SuiteApp made for that record ([below](#seeing-what-a-da-import-asked-of-netsuite)) |
| `UNEXPECTED_ERROR`, followed by `Possible reasons include` and three general guesses | A NetSuite DA import | The SuiteApp or bundle adds that same list to every `UNEXPECTED_ERROR`; it isn't a diagnosis, and NetSuite named no cause | Read the calls the SuiteApp made for the record ([below](#seeing-what-a-da-import-asked-of-netsuite)) -- the last one is where NetSuite failed -- and the values in the failed record's retry data. A case that repeats goes to NetSuite support, with those calls |
| `INVALID_INITIALIZE_REF`, or `INVALID_TRANSFORMATION` "Invalid transaction id …" | A NetSuite DA import that maps `Created From` (`celigo_nlobjTransformId`) | A mapped `Created From` makes the import transform that source transaction into the new record (an invoice or cash sale from a sales order, say) instead of creating one from scratch. `INVALID_INITIALIZE_REF` is NetSuite refusing that transform for this source; `INVALID_TRANSFORMATION` means the value isn't a transaction's internal id | Check the source transaction in NetSuite -- whether NetSuite offers this transform for it in its current status -- and that the row maps its internal id, not its document number. Then retry the failed records |
| `… Invalid Field Value NaN/NaN/NaN for the following field: <field>` (bundle and `suiteapp1.0` steps) or `… Invalid Field Value '<value>' for the following field: <field>` (`suiteapp2.0` steps) | A NetSuite DA import, on a date or date-time field | The value mapped to the field isn't a date the import can read: text in the date format of the NetSuite user the connection signs in as, or ISO 8601 and the other forms JavaScript's date parser reads. SuiteScript 1.0 steps then send `NaN/NaN/NaN`; a `suiteapp2.0` step refuses the value before NetSuite sees it. A date mapping that couldn't read its source sends the text `Invalid date` ([configuring-imports > Common Errors](../../configuring-imports/SKILL.md#common-errors)) | Send ISO 8601 (`YYYY-MM-DDTHH:mm:ss.SSSZ`), or set the row's `extractDateFormat` to the source's real format; the failed record's retry data shows the value. Then retry the failed records |
| `io_suiteapp_not_installed` "Integrator IO SuiteApp is not installed. …", or `sss_invalid_scriptlet_id` "We are currently unable to communicate with the 'Celigo integrator.io' …" (source `connection`) | NetSuite DA imports and lookups, RESTlet exports, a listener's setup | NetSuite answered that the Celigo RESTlet the step calls isn't there for this connection: the SuiteApp or bundle isn't installed in that account (or was removed), or the connection's role can't run its scripts | `celigo connections suiteapp-status <connectionId>` and the distributed ping ([above](#check-the-netsuite-side-first)) show which. A NetSuite administrator installs or updates it, or gives the role access |
| `INVALID_KEY_OR_REF` "Invalid `<field>` reference key `<value>`." | A NetSuite import row marked `internalId: true` | The row sends its value as an internal id, and NetSuite has no record it accepts for that value on this record: a name or other text where the id belongs, or an id that no longer resolves there (a deleted or inactive record, or one outside the transaction's subsidiary). The message names the field and quotes the value | Compare the quoted value with what the records that succeed send. Turn a name into its internal id with a lookup on the row (`lookupName`): a static `map` from name to id, or a search on the name with `resultField: internalid`, kept in `netsuite_da.lookups` and the same entry in the top-level `lookups`. Correct a stale id at the source. Then retry the failed records |
| `USER_ERROR`, with `source: application` | A NetSuite import | NetSuite refused the save: a required field is empty, or a rule in the account -- often its own user event script or workflow -- rejected the record. Celigo's hooks report their own `source` (`pre_map_hook` and the like for a JavaScript hook; `pre_map_hook_ss`, `post_map_hook_ss` or `post_submit_hook_ss` for the import's SuiteScript hooks), so NetSuite's code with `source: application` means NetSuite raised it. A postSubmit SuiteScript hook that rewords an error -- as an Integration App does when it puts its own sentence first -- changes that error's `source` to `post_submit_hook_ss` and keeps NetSuite's code ([Reading an App's Errors](../../managing-integrations/references/integration-apps.md#reading-an-apps-errors)) | Read the message for the field or condition it requires, and check whether the import sends it: the failed record's retry data shows what the step received, and the mapping what it writes. Map the field, or have a NetSuite administrator change the rule; don't edit a Celigo hook for it. Then retry the failed records |
| `SSS_TIME_LIMIT_EXCEEDED` or `SSS_USAGE_LIMIT_EXCEEDED` (possibly lowercase) | A NetSuite RESTlet (saved-search) export, partway through a run | One RESTlet call passed NetSuite's limit for a single execution: 300 seconds, or 5,000 usage units. Each call reads `netsuite.restlet.batchSize` records (default 1000), so a search that grew in NetSuite -- more rows, columns or formulas -- can push a call over with nothing changed in Celigo | Lower `netsuite.restlet.batchSize` ([below](#batch-size-previews-and-metadata)); `pageSize` doesn't size the call. Setting `restlet.columns` doesn't trim a saved search: the RESTlet adds those columns after the search's own and never drops one. If small batches still fail, the search's owner simplifies the search itself in NetSuite |
| `SSS_TIME_LIMIT_EXCEEDED` or `SSS_USAGE_LIMIT_EXCEEDED` on a batch of records at once | A NetSuite DA import | One call to the SuiteApp or bundle passed NetSuite's limit for a single execution. Each call carries `netsuite_da.batchSize` records (100 when unset), one call after another, and the SuiteApp or bundle saves them one at a time; a call that fails returns no result per record, so every record in it gets the same error -- including any it had already saved | Lower `netsuite_da.batchSize`. Before retrying an `add`, look in NetSuite for the records that call saved: a retry adds them again |
| `INVALID_LOGIN_ATTEMPT` "Invalid login attempt." | Every step on a token-based connection (`netsuite.authType` `token` or `token-auto`), and its test | NetSuite refused the connection's token. The Detail column of NetSuite's Login Audit Trail says why: `token_rejected` (the token was revoked, made inactive or can't be found), `permission_denied` (the user or role is inactive, the role was taken off the user, or it lacks token permission), `consumer_key_refused` (the integration record is blocked) | A NetSuite administrator fixes that cause or creates a new access token for the user and role named on the connection (`netsuite.roleName`, `roleId`). A person enters the new token on the connection in the Celigo UI (a `token-auto` connection authorizes again there, signing in with that role), tests the connection, then retries the failed records. Never take the token in chat ([configuring-connections > Minimum Required Fields](../../configuring-connections/SKILL.md#minimum-required-fields)) |

What `INVALID_KEY_OR_REF`, `USER_ERROR`, `SSS_TIME_LIMIT_EXCEEDED` / `SSS_USAGE_LIMIT_EXCEEDED`, `INVALID_INITIALIZE_REF` and `INVALID_LOGIN_ATTEMPT` mean is NetSuite's own documented meaning; no live call reached NetSuite to confirm it.

## Seeing What a DA Import Asked of NetSuite

- **The connection's debug log** lists, for each record a NetSuite DA import sends while it's on, the NetSuite calls the SuiteApp or bundle made to build and save the record (`nlapi calls registered for $R`), in order; the last one before an error is where NetSuite failed. Turn it on for a short window, run or retry the records, read it, and turn it off:

  ```bash
  celigo connections enable-debug <connectionId> --duration 15
  celigo connections debug-logs <connectionId>
  celigo connections disable-debug <connectionId>
  ```

  Over the REST API that's `PATCH /v1/connections/{_id}` on `/debugDate`, then `GET /v1/connections/{_id}/debug`.
- **`Print Nlapi Debug Logs`** -- a checkbox the field list offers on every record type (`celigo_write_log`) -- mapped to `true` also writes a debug entry for each of those calls into the Celigo RESTlet's own execution log in NetSuite.

## Wrong Results With No Error

- **A DA lookup whose key renders empty searches `isempty`.** When the source path a criterion reads is null or missing, the lookup searches that field for blank values instead of failing: two or more blank records fail the record with `VALUE_LOOKUP_FAILED` ("More than one match for `"[<field>,"isempty"]"`"), none fail it with "Could not find a match", and exactly one silently becomes the match. Branch on the key inside the expression: send a record without one to a fallback record, or render a value that can't match and set `allowFailures: true` with a `default`.
- **Saved-search columns become fields by their Custom Label.** A column without one takes its column id, and an unlabeled formula column its type and position (`formulatext_txt_3`), so adding or moving a column in the search can rename the field the export's mappings read, and they find nothing. A select column's field holds the value's display text, not its internal id, and two columns with the same label become one field holding an array. Give every column a mapping reads its own Custom Label.
- **A saved search edited in NetSuite changes the export.** The export runs the search's current definition, so its output changes with no change in Celigo. When the output changed and the export didn't, open the search in NetSuite.
- **A formula criterion that's false for every record returns no rows** and no error. Check the formula with a preview that should return records.
- **A listener that never fires** is usually scoped away from the save: records a Celigo NetSuite import writes arrive in the `restlet` context, which the defaults leave out ([gotchas 14 and 15](../SKILL.md#gotchas)), and the listener's deployment follows its flow being enabled ([Listeners](../SKILL.md#listeners)).
- **The mapping Preview of a NetSuite DA import can't evaluate `[*]` inside a block-helper argument** (`{{#if line_items[*].x}}`, `{{#contains line_items[*].sku "_"}}`): the sublist comes back empty with no error, and a record using `<array>.@index.<field>` is dropped. An empty preview says nothing about such an expression; check it with a run.

## Batch Size, Previews and Metadata

- **`netsuite.restlet.batchSize`** (default 1000) sets how many records each NetSuite call returns; the export's `pageSize` doesn't. The RESTlet caps a call at 1000, so a larger value acts as 1000. Larger batches mean fewer round trips but more NetSuite governance and memory per call, so lower it for large records, or when a call stops at NetSuite's per-call limit (`SSS_TIME_LIMIT_EXCEEDED`, above). A test run or preview caps each request at the export's `pageSize` (default 20) instead, so it never exercises the run's batch size.
- **Metadata is cached.** `celigo metadata types <connectionId>` lists record types and saved searches, and `celigo metadata fields <connectionId> <recordType>` a record type's fields; after a field, record type or saved search is created in NetSuite, read again with `--refresh` ([step 4](../SKILL.md#4-query-metadata-for-the-target-system)).
